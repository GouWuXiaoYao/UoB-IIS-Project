# System diagram

`system-diagram.png` is the figure for §2 and §3 of `docs/A2_Report_3138100.docx`. It shows the
data flow of the prototype, the boundary where a model would sit, and what is implemented,
simulated or planned. `README.md` (this file) is the evidence table the figure's numbers resolve
to.

Generated by `tools/make_diagram.py` with the repository's own PNG writer (`analysis/png.py`), so
the figure needs no third-party dependency and can be rebuilt offline:

```
python tools/make_diagram.py            # rewrite system-diagram.png
python tools/make_diagram.py --check    # exit 1 if a drawn stage no longer exists in the code
```

`--check` reads `NODES` in the generator: each drawn box names a file and a symbol that must still
appear in that file. A stage cannot be drawn after it has been deleted, so the picture cannot
outlive the code it claims to describe.

## What the three states mean

| State | Drawn as | Means in this report |
|---|---|---|
| implemented | solid black frame, white fill | The code is in this tree and runs offline; a test exercises it. |
| simulated | dashed blue frame or dashed blue edge | The data comes from a script, not from a model or a person. `recordings/` holds six files, each carrying `"source": "sim"`. |
| planned | grey frame, grey fill | Specified, not run. No data exists for it: the human study (SPEC §5.2) and the paid API call (`mode=live`). |

Flows follow the same convention: solid = exercised by the shipped commands, dashed blue = a
file read that stands in for a model reply, dashed grey = not exercised at all.

The AI's state is deliberately explicit in column B. The client is **implemented code**, but its
output in this study is a **replayed recording**: there is no socket, no key and no network on any
path the shipped commands take. The only code that would call a paid endpoint is
`govern/llm.py:285 _live()`, and no test or command reaches it — `tests/test_llm.py` exercises that
path only against a loopback stub. That is why the external API is grey and edge 8 is dashed.

## Control flow, in words

The gate is the control point, not a dialog. `Session.generate()` raises `GateClosed` unless every
required item is confirmed, and the C0 baseline passes through the same interface with an empty
card, so the two conditions differ only in whether the check happens. Everything downstream of the
gate — suggestion, patch application, scoring, logging — is identical in both conditions, which is
what makes the two columns comparable in the analysis.

## What is deliberately not in the figure

- No network edge is drawn to the outside world; edge 8 stops at the API box and is dashed.
- No participant appears in any box or edge except the grey study node.
- `runs/` is not a drawn input: it is produced by the runner (edges 12–14), and the analysis reads
  it rather than any in-memory state, so a reader can recompute every number from the logs.

## Honest limits of the figure

- The bitmap font in `analysis/png.py` has no lower case and no true italics; headings are upper
  case by necessity, not by style.
- The figure keeps to the six flows the report needs. It is not a complete call graph: constructor
  wiring, error paths and the CLI entry points are omitted.
- Node positions were chosen for legibility, not to imply timing; the only ordering claim is the
  left-to-right reading of columns A → B → C.
