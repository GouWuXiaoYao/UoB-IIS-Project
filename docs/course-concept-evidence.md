# 课程概念证据核对（W1–W4）

用途：为报告 §Design rationale 提供**可核实**的课程概念依据。本文件只核对证据，不改代码、不写报告。

材料：`IIS_W1-4_概念与知识点汇总.docx`（11 页，周次 W1–W4、十二讲 L01–L12、§01–§07 七个小节）。评分说明要求点名 W1–4 的概念并说明它如何影响决策。

**定位方式**：该册没有讲义页码，用的是"章节 + 讲次/术语条目"的自有编号（如 `§04 L12`、`§06 术语表 W2`）。因此下表给的是**段落级**位置。若报告需要讲义原件的页码/幻灯片号，见文末"需要的材料"。

**证据强度**：
- **强** = 概念在该册的框架总表或术语表里被明确命名，且该册给出了机制或补救手段，而我们的实现正是那个手段（不是主题相似）。
- **中** = 概念被明确命名，但把我们的决策挂上去需要一步解释。
- **弱** = 只有主题相似，不足以作为报告依据。
- **误配** = 同名不同义，写进报告会被当成术语堆砌。

## 2. 对 `docs/compliance-check.md` §2.1 四个候选的判定

我在合规检查里给的四个候选是"我建议、不是评分说明里的"，现在逐条核对：

| §2.1 原候选 | 判定 | 说明 |
|---|---|---|
| 从不预勾选 ↔ **默认效应 / 机械确认（confirmation fatigue）**；识别优于回忆 | **不支持（前半）+ 中（后半）** | 该册**没有**"默认效应"或"确认疲劳/机械确认"条目，`§06` 全表无此词。而"机械确认"来自 A1 引用的 Shihab et al. (2025)，属**文献依据**，不是课程概念。写报告时必须分开标注，否则等于把文献塞进课程概念。可保留的只有 `Recognition vs recall`（中） |
| 拦截时列陈述文本 ↔ **系统状态可见性、错误信息用用户语言** | **部分支持** | 可见性有（W1 `Visibility`）；但更强的依据是 L06 的 `show what was heard` 与 L07 的 `clarify`。"错误信息用用户语言"在该册无对应条目——`§04` L07 的 Grice `manner` 是**会话准则**，不是错误文案原则，勉强引用会被看穿 |
| 禁用 + 说明原因 ↔ **防错优于纠错；执行鸿沟** | **部分支持** | "防错优于纠错"不是该册措辞，该册写的是 slip 的补救 = `constraints / confirmation / undo`；`Gulf of execution` 确有（`§06 W2`）。改写成"约束与意符"即可升为**强** |
| 空态文案 ↔ **状态可见性** | **支持但弱→中** | `Visibility` 明确存在；但需补一句"它对应 system image 的可读性"才够，单说"避免看起来像坏了"是常识，不是课程依据 |

**结论**：四个候选里，只有第 2、3 条经改写后能站住，第 1 条前半必须撤掉，第 4 条需要补锚点。真正强的依据不在 §2.1 那四条里，而在 **L12 执行前五项检查**（Confirmation）、**L12 可逆×可见矩阵**、**L06 的 show what was heard**、**EX 的无被试评估**、**§05 的系统日志与 baseline**——这五条才是这份原型的课程骨架。
