# Rubric mapping — marking criterion → evidence trail

> **What this file is not.** It does not infer marks, and it does not restate the marking criteria. The band descriptors of the A2 rubric are quoted in
> [SPEC.md](SPEC.md) 0.2; this file does one thing: **it grounds every marking criterion in evidence inside the repository that a third party can re-check**
> (file:line, test name, reproducible command). Any row without evidence is marked `to be added`; nothing is written as "done".

Current coverage: **M0–M13** — the section 1 table is a summary, and each milestone's own rows (§2 … §2l) are the current record.
Sections 1 and 2 were written milestone by milestone, so a status cell there records the state **at the time that section was written**; where a later section contradicts it, the later section wins.
Line numbers drift as the code changes, **so the test name is the primary key**; line numbers are only for fast location.
Last updated: 2026-11-14.

| 5 | Deterministic output: the same input twice gives the same `impact_set_hash` | `govern/impact.py:265` `impact_hash()` takes a SHA-256 over sorted items; the sort key is `(category, symbol, files, detail)`, independent of file traversal order | `test_same_input_same_hash` (`:116`), `test_hash_is_stable_across_processes` (`:122`, recomputed in a child process to catch set/dict iteration order) |

**Why recall=1.00 does not mean "memorising the answer"**

- The labels in `impact_labels.json` were written in **M2**; the analyser only exists from **M3**, and `analyze()` reads only the repository AST — it never reads the label files.
- The operational definition of a contract is in the module docstring: **if a module's top-level "value" (not a function) is read by ≥ 2 modules inside the package, those readers form a contract over the same assumption**; the anchor is the module the other readers actually call.
- Counter-evidence: `test_an_extra_reader_adds_a_contract_and_costs_precision` (`tests/test_impact.py:96`) adds a new module that reads `state.TAX_RATE` to a real repository and asserts that the analyser **adds** one unlabelled contract and that precision then falls below 1.0 — the output really is driven by the code.

**Precision scope (an honest statement)**: `recall_precision()` counts only the two labelled classes (`global_var`, `cross_module_contract`) in the denominator;
`side_effect` / `test_impact` / `other` are advisory items that serve the evaluation card (M4/M5), the labels never intended to enumerate them, and counting them in the denominator would only punish the analyser for being useful.

## 2l. Analysis layer → evidence (`analysis/`, statistical conclusions read out of the logs)

The log is the only data source (AGENTS §2.6), so `analysis/` reads only `runs/<run_id>/logs/*.jsonl`: it does not modify `govern/`, does not re-run experiments and pulls in no third-party library (AGENTS §1: `pip` is unavailable on this machine, and there is no `pandas`/`scipy`/`openpyxl`/`matplotlib`). The xlsx and the PNGs both come from minimal writers written in this repository.

The only metric that enters the multiple-comparison family is task duration `elapsed_ms`: difference −2.33 ms, t(5) = −2.44, p = 0.0578 (still 0.0578 after Holm, not significant). The seven outcome metrics (`debt_delta`/`vuln_delta`/`n_fail`/`lines_added`/…) have **identical** differences within every pair, so both t and Wilcoxon return `n/a`, and the `Note` column states "the standard error is 0, the statistic is 0/0, not infinite evidence" — printing them as p<0.001 would be outright forgery.

**Honest record (the boundary of this layer)**

- **This is not evidence that governance works**. The operator is a script (`_rehearse` in `govern/run.py`), and C0 and C1 receive the **same** replayed suggestion, so by design the outcome metrics must be equal. The value of the analysis layer is to prove "the metrics can be computed from the logs, and a wrong computation gets caught", not to prove the experiment found something.
- **A structural zero cannot be treated as an effect size**: `gate_latency_ms` and `blocked_attempts` are always 0 in the baseline (C0 has no card and no gate), and "constant 0 vs a measured value" is not a between-arm difference. They are marked `structural zero in baseline` and excluded from the multiplicity family; `test_report_marks_a_structural_zero` (`:346`) pins that label.
- **The mixed-effects model is unidentifiable on real data**: one participant and six tasks make the random intercept collinear with the intercept, so the function returns an explanatory string instead of a forced fit. Its numerical correctness is verified only in tests with two-group structures (`test_mixed_model_recovers_the_within_group_difference`) — this is "implemented", not "used".
- **The PNGs are not publication-grade typesetting**: a 5×7 bitmap font, capitals only, 900 px wide. Readable, reproducible, no third-party dependency, but in a paper the captions and tables must carry the detail.
- **The missing-data checks are all zero on the real run**: `E-SIM-01` has no missing cell, no bad line and no unfinished session, so the actual triggering of the three checks is only exercised on constructed fake runs (`StudyTests`). That is an honest gap, not coverage.
- The analysis layer does not change a single byte of `govern/` and consumes nothing outside `runs/` (`R-DEMO` and `R-ADHOC` sitting alongside would turn 12 sessions into 19, so `_resolve()` requires an explicit `--run-id`, `test_two_runs_need_an_explicit_choice`).
