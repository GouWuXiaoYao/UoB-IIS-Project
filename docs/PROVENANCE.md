# Development provenance ledger (SPEC M11)

This file is **data**, not narrative: one checkable record per row, validated line by line by `python -m govern.provenance --check`.
Rules (see `docs/SPEC.md` M11):

- `module` must be one of M1–M11, and every module needs at least one row;
- `origin` may only be `original` / `reused` / `assisted`, and all three must appear — filling every row with original counts as not really distinguishing them;
- `assisted` rows must have both a `decision` (why it was kept) and a `check` (how it was verified);
- the `source` of a `reused` row must point at a path that really exists in the workspace.

**Two honest declarations**:

1. Most of this project's code drafts were generated by an AI programming assistant, so `assisted` rows are the largest share. This is neither modesty nor a disclaimer — A2 requires the three origins to be distinguished, and this is that distinction itself.
2. `original` rows record **the author's own rulings and rules** (the scope decisions Q1–Q8, the product red lines); `reused` rows record structure taken from `参考代码库/`; `assisted` rows record parts drafted by the AI and then reviewed and changed by the author.
